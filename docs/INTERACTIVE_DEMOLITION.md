# F9 interactive demolition

AVBD is the default solver (`3` selects AVBD; `4` selects TGS). Do not launch
with `BB_SOLVER=3` unless you explicitly want TGS. The F7 measurements favor
AVBD for cost; that is not yet a performance measurement of destruction.

Press F9, then Space. Hold the left mouse button on the steel club, move the
cursor to lift/swing it, and release while moving to throw. Grabbing an end
allows rotation around the selected point. Right drag operates the camera;
R rebuilds the scene. Release preserves linear and angular velocity.

The mouse constraint solves three sequential velocity rows at the local grab
anchor. Each row includes inverse mass plus rotational effective mass, and
reads velocities after the previous row. Target speed remains capped at 12 m/s.
This replaces the torque-free center-of-mass pull and explicit spin damping.

Each timber frame is one connected voxel body with impact fracture enabled.
The existing fracture path carves/partitions its voxels, rebuilds connected
components, and creates dynamic fragments. These are freestanding structures,
not anchored buildings. Currently fracture events are generated by the AVBD
impact pass; switching to TGS does not provide equivalent destruction.

This is a first interactive destruction scene, not a structural stress model.
Load-dependent failure, persistent damage, foundations and breakable joints
between separate bodies still require a structural-integrity system. Collision
coloring alone cannot provide those behaviors.

Mouse presses are latched until a physics step consumes them. A render-only frame
cannot erase a pending click, and catch-up steps do not repeat its raycast. The
existing simulation completion wait protects the mapped CPU/GPU input bridge.

## Validation (RTX 4090, LXC 110)

C++ build and both existing CTest suites pass. A native X11 mouse test picked
the club once, lifted it with visible rotation, and released it before the first
fracture event (impulse 212.043, threshold 30). The scene grew from 5 to 11 bodies.
Khronos synchronization validation reported zero errors, warnings and hazards;
PERF reported no NaNs. The frames also remained intact before interaction.
This is a functional smoke test, not a long-run fracture stability benchmark.
